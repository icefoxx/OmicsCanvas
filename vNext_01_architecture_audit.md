## 1. Existing plugin system

**Layout.** All user-facing plotters live under `plugins/<id>/`. There are **47** directories with `plot.R`.

| Asset | Count | Notes |
| --- | ---: | --- |
| `plot.R` | 47 | Required renderer |
| `config.yaml` | 45 | Missing: `intragroup_correlation`, `volcano_plot` |
| `params_schema.json` | 45 | Same two missing |
| `examples/` (indexed bundles) | 45 | Same two missing |
| `README.md` | 45 | Same two missing |
| `SKILL.md` | 21 | See §2 |
| `run_all_examples.sh` | 41 | Gallery smoke runner |
| `plot.py` | 0 | No Python plotters |

**Runtime contract (stable).** From repo root:

```bash
Rscript plugins/<id>/plot.R --input <table> --params params.json --output <dir>
```

Optional flags used by `plot_web.app.build_command`: `--input2`, `--annot`, `--expr`, `--genesets`, `--embed`, `--lineages`, `--col_annot`, `--row_annot`, `--marks`, `--nodes`, `--matrix`, `--comparisons`. Some plugins add extra flags (`--scores`, `--lower`, `--features`, `--row-annot` vs `--row_annot`) that the generic dispatcher may not always map **(uncertain: flag-name drift across plugins)**.

**Discovery.** `plot_web` lists plugins by globbing `plugins/*/config.yaml`. The two incomplete plugins (`intragroup_correlation`, `volcano_plot`) are **not** in Gallery/Editor/AI catalogs even though `plot.R` exists.

**`config.yaml` fields (typical).** `id`/`name`/`display_name`, `version`, `description`, `language: R`, `entrypoint: plot.R`, `category`/`subcategory`, `status`, `inputs[]`, `outputs[]`, `runtime.command`. Categories are also **hard-coded** in `plot_web/app.py` (`normalized_category`, `default_subcategory`) when config is missing or generic (`"Plot"`).

**Examples.** Two layers coexist:

1. **Legacy files at plugin root:** `example_*_params.json` + `example_input.csv` (and siblings).
2. **Bundles under `examples/<id>/`:** `manifest.json`, `params.json`, `input/`, `expected/result.png`, plus `examples/index.json`. Generated by `plugins/example_gallery_helpers.sh`.

`list_example_params()` prefers indexed bundles when present, else `example_gallery.json`, else root `example_*_params.json`.

**Sibling code, not plugins.** `R/` is a copy of SCA helpers (`basic_plots/`, `advanced_plots/`, `data_format_validation/`). Several plugins keep `reference_sca_helpers/` and wrap those functions (`advanced_dim_plot`, `sca_volcano_plot`, `group_heatmap`, etc.). Gallery/AI never call `R/` directly.

**Template.** `plot-plugin-template.R` documents CLI, `error.json`, and outputs (`result.svg/pdf/png`, `figure.json`, `run.log`).

## 3. Rendering languages / frameworks

**Language:** R for all 47 `plot.R`. FastAPI infers Python if `runtime.command` starts with `python` or `entrypoint` ends in `.py`; **no plugin uses that path**.

**Static stack (dominant):**

- `ggplot2` + `ggsave` for SVG/PDF/PNG (all 47 write those filenames; ~44 source ggplot2).
- `optparse` + `jsonlite` for CLI/params.
- `ggrepel` on labeled plots (e.g. lollipop).
- **ComplexHeatmap** in `group_heatmap` and `intragroup_correlation`.
- Grid/grob helpers via SCA copies for dim/feature/stat plots.

**Interactive (optional, ~21–22 plugins):** Plotly + htmlwidgets → `result.html`. Typically gated on `interactive: true` and `requireNamespace('plotly')`. If missing, plugins write a stub HTML or skip. Static SVG/PDF/PNG remain the contract.

**Not used as plotters:** Python matplotlib/plotly, JS charting in the renderer. The web UI is vanilla JS (`plot_web/static/*.js`) driving the R job.

**I/O:** R readers are CSV/TSV/TXT. Excel is converted to CSV in Python (`plot_web/table_io.py`, openpyxl) **before** Rscript. `.rds`/`.h5ad` appear in example-extension allowlists but are not a general plugin input **(uncertain how many plotters actually read them)**.

## 4. Existing schemas

There is **no common PlotSpec** in the runtime. Three heterogeneous schema layers exist:

### 4.1 `params_schema.json` (UI control surface)

45 files. Not JSON Schema Draft for PlotSpec. Three observed shapes (from a full scan):

| Kind | n | Example |
| --- | ---: | --- |
| Sectioned UI map `{section: {param: {type, label, default, options}}}` | 36 | `interactive_enrichment_lollipop` (`data`, `canvas`, `lollipop`, …) |
| `groups` + `properties` wrapper | 8 | several `interactive_*` (e.g. `interactive_radar_plot`) |
| JSON-Schema-ish (`properties` nested) | 1 | normalized by `plot_web/schema_normalize.py` |

`plot_web.schema_normalize.normalize_params_schema()` flattens these into `{section: {key: leaf}}` for Gallery/Editor. Leaf types: `column`, `columns`, `string`, `number`, `boolean`, `color`, `select`, `string_array`, `object`, `textarea`.

**This schema is not validated at run time.** Invalid params are not rejected by FastAPI; R plugins autodetect columns, apply aliases, and `fail()` only on hard errors.

### 4.2 `config.yaml`

Plugin metadata + input list. Some configs omit `language`/`category` (filled by inference). `parameters` in config is a fallback if `params_schema.json` is absent (`effective_params_schema`).

### 4.3 Draft PlotSpec (`vnext/plotspec/`) — **unwired**

`schema.json` (Draft 2020-12) defines `spec_version`, `skill`, `input`, `mapping`, `transform`, `statistics`, `visual`, `export`, `legacy_params`, `provenance`. `model.py` has load/dump/`validate_schema`/`empty_spec`/`merge_defaults`/`round_trip`.

**Not used by:** `plot_web/app.py`, any plugin, editor, job `params.json`, or `figure.json`. Treat as Phase 1 starting point, not a live contract.

### 4.4 `figure.json` (post-hoc metadata)

Every `plot.R` writes plugin-specific JSON (keys vary: `figure_type`, `analysis`, `style`, `data`, `layers`, `export`, `plotly`, …). It is **descriptive output**, not an input spec. Structure is not shared. It is **not** a PlotSpec and **not** sufficient for lossless round-trip of all `params.json` fields **(uncertain per plugin)**.

## 5. Session representation

Several independent “sessions” exist. None store a PlotSpec.

| Store | Path / API | Contents |
| --- | --- | --- |
| Workspace state | `plot_web/storage/state/current_state.json`; `GET/POST /api/state`, `/api/state/save`, `/api/state/load` | `active_dataset_id`, `active_plugin_id`, `data_map.nodes/edges` (dataset → plot_run → result), `recent_jobs`, `ui.selected_mode` |
| Jobs | `plot_web/storage/jobs/<job_id>/job.json` + `params.json` | `job_id`, `figure_id`, `plugin_id`, status, paths, `uploaded_files`, optional `ai` block |
| Uploads | `plot_web/storage/uploads/<job_or_session>/` | Input tables; Excel originals + converted CSV |
| Results | `plot_web/storage/results/<job_id>/` | Figure files + logs |
| Datasets | `plot_web/storage/datasets/<id>/dataset.json` | Uploaded/derived tables |
| AI session | `uploads/ai_*/session.json` | `session_id`, goal, table profile, recommendations, intent, skills |
| Editor UI | in-memory `state.params` in `editor.js`; `localStorage` only for floating-toolbar position | Flat param map |
| Gallery UI | `app.js` `state.serverState`; Save Session posts that object | Graph of recent runs, not params |

**Save Session / Load Session** persist the data-map graph, not editor params and not a PlotSpec. Re-running a figure uses `POST /api/results/{job_id}/rerun` if original upload files still exist, plus the stored `params.json`.

**Params in a job** are a **flat JSON object** (plus injected `plugin_id`, `dispatch_mode`). Nested schema sections are UI-only; Editor writes `state.params[control.key]`. Example (`interactive_enrichment_lollipop` basic):

```json
{"title":"Pathway enrichment","xlab":"...","sort_by":"value","group_colors":{...},"interactive":false,"width":9,"height":7}
```

R helpers (`val()`, `val_any()`, aliases) read top-level keys. Some plugins accept grouped aliases **(uncertain which still accept nested groups)**.

## 6. AI Studio execution path

Implemented in `plot_web/app.py` + `plot_web/ai_assistant.py`. UI: Gallery **✦ AI Studio** (`index.html` / `app.js`).

```text
Upload CSV/TSV/XLSX
  → profile_table (columns, numeric/categorical, tags)
  → recommend_plugins (deterministic RULES on tags/colnames/goal keywords)
  → optional refine_with_spacexai (LLM JSON rerank; plugin_id must be in candidates)
  → match_skills (authoring skill, not renderer)
  → summarize_intent (rules, optional LLM)
  → POST /api/ai/build-demo or /api/ai/pipeline
       → build_params_for_plugin (heuristics) + subsample rows
       → on failure: plugin built-in demo
       → same Rscript job path as Gallery
  → POST /api/ai/explain (LLM or English template)
  → POST /api/ai/chat
```

**Default engine is rules.** LLM is optional (`XAI_API_KEY` / `OPENAI_API_KEY` / `OPENCODE_API_KEY`). If no key, recommend/explain still work.

**Deterministic boundary (vNext) is not present.** After ranking, the path still:

- guesses column mappings (`category_column`, `x_column`, …);
- silently falls back to built-in demo data;
- injects visual defaults (`title`, `width`, `dpi`);
- does not emit or validate a PlotSpec;
- does not run a scientific validator.

LLM never writes R code at runtime (good). It also never produces a typed spec (gap). Plugin choice and params remain heuristic.

**Catalog used by AI:** only plugins with `config.yaml`. Incomplete `volcano_plot` / `intragroup_correlation` are invisible to recommend.

## 7. Export architecture

**Required outputs (template + most configs):**

| File | Role |
| --- | --- |
| `result.svg` | Vector (ggsave) |
| `result.pdf` | Vector |
| `result.png` | Preview / gallery (often 300 dpi) |
| `figure.json` | Plugin metadata |
| `run.log` | Timestamped log |
| `error.json` | On failure only |

**Optional / plugin-specific:** `result.html` (Plotly), `selected_rows.csv`, `selected_points.csv`, `selected_features.csv`, subset/Venn tables, `matrix_used.csv`, `annotation_used.csv`, `enrichment_results.csv`, cluster order CSVs. FastAPI maps a fixed filename set in `output_file_for_type` / `output_urls_for_dir`. Extra files on disk may not be downloadable via the typed API unless they match that map.

**Dimensions:** inches + dpi in params (`width`, `height`, `dpi`), not mm. vNext PlotSpec draft prefers `width_mm`/`height_mm` — adapter needed.

**Reports:** `POST /api/reports/create` writes a Markdown file under `plot_web/storage/reports/` with job status + PNG links. Not a reproduction bundle (no checksums, no spec, no methods text, no environment versions).

**No provenance package:** no input checksum, no params/PlotSpec hash, no R/package versions, no methods paragraph, no zip bundle, no `omicscanvas reproduce` CLI. `vnext/provenance/` and `vnext/reproduce/` are empty directories.

## 11. Conflicts with vNext spec + recommended resolutions

| # | Conflict | Resolution |
| --- | --- | --- |
| C1 | Spec file names (`schema.json`, `defaults.yaml`, `renderer.*`) ≠ `params_schema.json` / `config.yaml` / `plot.R` | **Do not rename 45 plugins.** Registry maps current files. Add vNext files beside them for the reference skill first. |
| C2 | SKILL.md on 21/47 plugins; README is the real doc for the rest | Treat README as SKILL fallback. Do not block Gallery on SKILL.md. Backfill SKILL during family migration (Phase 6). |
| C3 | Params are flat JSON, not PlotSpec | Introduce PlotSpec as a **wrapper**. Put unmapped knobs in `legacy_params`. Adapter `plotspec → params.json` calls existing R. Lossless round-trip = PlotSpec + `legacy_params` + file paths. |
| C4 | `figure.json` ≠ PlotSpec | Keep writing `figure.json` for the editor. Add `plotspec.json` (and later provenance) as extra artifacts. Do not overload `figure.json`. |

## 12. Chosen incremental strategy for Phases 1–6

**Principle:** adapter-first, one reference skill, no mass rewrite, Gallery/AI stay on `params.json` until an adapter is proven.

```text
User/AI intent
  → (optional) LLM/rules propose PlotSpec
  → schema + scientific validation          [new]
  → adapter: PlotSpec → existing params.json [new]
  → Rscript plugins/<id>/plot.R             [unchanged]
  → result.* + figure.json                  [unchanged]
  → plotspec.json + provenance (later)      [new artifacts]
```

### Phase 1 — PlotSpec + Registry

- Keep/extend `vnext/plotspec/schema.json` + `model.py` (round-trip, `legacy_params`).
- Registry loads `plugins/*/config.yaml` (45 entries). Incomplete `plot.R`-only dirs are recorded as `status: unregistered`.
- Do **not** require SKILL.md. Record `has_skill`, `has_schema`, `entrypoint`.
- Adapter interface: `to_legacy_params(spec) -> dict` (identity via `legacy_params` initially).
- **Do not** change `POST /api/plugins/{id}/run` body yet; add optional `plotspec` field that is stored and converted.
- Deliverable: `vNext_02_plotspec_and_registry.md`. Acceptance: lossless round-trip for supported fields; registry loads 45 plugins without id collisions.

### Phase 2 — Reference skill `interactive_enrichment_lollipop`

Chosen because it already has SKILL.md, sectioned schema, example bundles (incl. `oct4_enrichment`), `run_all_examples.sh`, and is named in the framework.

- Add skill-side `defaults.yaml` (visual/export only; scientific mapping required).
- Add validator: signed effect column, NES vs p-value confusion, required `mapping.term`/`mapping.effect`.
- Adapter fills `category_column`/`value_column`/… from `mapping` + `legacy_params`.
- Render still via existing `plot.R`.
- Write `plotspec.json` next to `figure.json` for this skill only.
- Deliverable: `vNext_03_reference_skill_migration.md`.

### Phase 3 — Scientific validator framework

- Global / family / skill rule interfaces in `vnext/validate/`.
- First family: enrichment (lollipop + later fgsea).
- Structured errors/warnings; **no silent p → FDR**.
- Other plugins keep current R autodetection until migrated.
- Deliverable: `vNext_04_scientific_validation.md`.

### Phase 4 — Provenance + reproduction

- Checksums of inputs, hash of PlotSpec, skill id/version, R + package versions (from `sessionInfo()` or a sidecar).
- Bundle: data snapshot + params.json + plotspec.json + figure files + methods stub (template from PlotSpec, not LLM-invented).
- CLI under `vnext/cli` wrapping the same Rscript command already in example manifests.
- Job rerun remains the FastAPI equivalent.
- Deliverable: `vNext_05_provenance_and_reproduction.md`.

### Phase 5 — Testing + CI

- pytest: PlotSpec schema, registry load, lollipop adapter, validator cases.
- Keep `run_all_examples.sh` as optional/nightly visual smoke; CI gate starts with **canonical examples of the reference skill** (3 bundles: basic, oct4, interactive).
- Do not require image-diff for all 45 plugins in the first CI.
- Deliverable: `vNext_06_testing_and_ci.md`.

### Phase 6 — Remaining skills by family

Order (matches spec; adjusted to repo ids):

1. Enrichment: `interactive_enrichment_lollipop`, `fgsea_enrichment_plot`
2. Scatter / volcano: `sca_volcano_plot`, `quadrant_correlation_scatter`, `regression_scatter_plot`, `highlight_effect_plot` (defer incomplete `volcano_plot`)
3. Expression / statistics: `stat_plot`, `exp_stat_plot`, `violin_plot`, `interactive_violin_plot`, `interactive_ridgeline_plot`, `interactive_histogram_plot`, bars/combo
4. Heatmaps / clustering: `group_heatmap`, `interactive_clustered_heatmap_plot`, `interactive_correlation_matrix`, `threshold_matrix_heatmap`, `balloon_plot`, …
5. Dimension / feature: `advanced_dim_plot`, `advanced_feature_plot`, `feature_density_plot`
6. Trajectory: `lineage_plot`
7. Overlap: `dynamic_venn_diagram`, `interactive_upset_plot`
8. Flow / network / misc: alluvial, sankey, networks, pie, radar, motif, genomic tracks

Do **not** force one mapping vocabulary onto heatmaps vs volcanoes. Each family gets mapping roles + `legacy_params` for the ChiPlot-sized control surface.

Incomplete plugins (`intragroup_correlation`, `volcano_plot`) join a family only after `config.yaml` + `params_schema.json` + one example bundle.
