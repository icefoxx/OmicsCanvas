# 01 — Plugin contract

## Directory layout

```text
plugins/<plugin_id>/
  config.yaml            required  metadata, inputs, outputs (below)
  params_schema.json     required  UI controls (02)
  plot.R                 required  entrypoint (03)
  README.md              required  input format, main parameters, run command, outputs
  examples/
    index.json           required  list of example bundles (05)
    <example_id>/        required  manifest.json, params.json, input/, expected/result.png
  all_examples_gallery/  generated by scripts/sync_gallery.py (05)
  vnext/metadata.yaml    generated by python -m vnext.cli migrate — never edit by hand
  SKILL.md               optional  plugin-specific notes for agents (no absolute paths)
```

`<plugin_id>` is snake_case (`[a-z][a-z0-9_]*`), descriptive of the figure, not of a tool or paper
(`enrichment_lollipop`, not `<toolname>_lollipop` or `fig3_plot`). Prefix `interactive_` only when the
plugin also writes a Plotly `result.html`.

Do not add `example_*_params.json` or `example_input.csv` at the plugin root (legacy); examples
live in `examples/`.

## Command line

```bash
Rscript plugins/<id>/plot.R --input <table> --params <params.json> --output <dir> [--<extra> <file> …]
```

- `--input` is the main table. Extra uploads are declared in `config.yaml` `inputs` and passed as
  `--<input id>`, or as `inputs[].flag` when the flag differs (`{id: expression, flag: --expression}`).
- `--params` may be missing or `{}`: every parameter has a default.
- `--output` may not exist yet: create it. Delete stale result files from earlier runs at start.
- The working directory is the repository root, but never rely on it: resolve repository files
  relative to the script path (template: `script_dir`, `repo_root`).
- plot_web runs R with `R_PROFILE_USER=R/runtime/omicscanvas.Rprofile`, which seeds the RNG from
  `params.seed` (default 42). Do not override it. The same profile wraps
  `htmlwidgets::saveWidget` so missing pandoc does not abort the job: self-contained HTML is
  attempted when pandoc is present, otherwise a non-selfcontained file (or a stub page) is
  written and PNG/PDF still succeed.

## config.yaml

```yaml
id: my_plot                       # = directory name
name: My Plot                     # display name
version: 1.0.0                    # MAJOR.MINOR.PATCH; bump MINOR for new parameters, MAJOR for renamed/removed ones
description: One sentence — what the figure shows, not how it is built.
language: R
entrypoint: plot.R
category: Scatter                 # Studio sidebar group, allowed list in 04
subcategory: General              # free text, short; group siblings consistently
status: beta                      # stable | beta | experimental | deprecated
inputs:
- id: input                       # the main table is always `input`
  type: table                     # table | matrix | file
  formats: [csv, tsv, txt]
  required: true
- id: annot
  type: table
  required: false
  flag: --annot                   # only when the CLI flag is not --<id>
outputs: [result.svg, result.pdf, result.png, figure.json, run.log, data_used.csv]
runtime:
  command: Rscript plugins/my_plot/plot.R --input input.csv --params params.json --output output_dir
```

Rules: `id` (not `name`) identifies each input — the runner ignores entries without `id`.
`outputs` lists every file the plugin writes, including extra CSVs and `result.html`.

## Outputs

| File | When | Content |
|---|---|---|
| `result.svg`, `result.pdf`, `result.png` | success | the same figure; sizes from `width`/`height` in inches, `dpi` for PNG |
| `figure.json` | success | see below |
| `run.log` | always | timestamped lines: inputs used, rows dropped and why, fallbacks taken |
| `result.html` | `interactive_*` plugins | self-contained Plotly widget |
| `*_used.csv`, `selected_rows.csv` | recommended | the data actually drawn after filtering |
| `error.json` | failure | `{"error": short title, "detail": specifics, "suggestion": what to change}` |

On failure: write `error.json`, log the message, exit with status 1, and leave no partial
`result.*` files. Messages name the parameter or column involved and how to fix it
("Column for x_column not found — set x_column to one of: a, b, c").

### figure.json (minimum)

```json
{
  "plugin": "my_plot",
  "version": "1.0.0",
  "data": {"rows": 120, "dropped_rows": 3, "mapping": {"x": "dim1", "y": "dim2", "group": "cluster"}},
  "layers": ["point", "lm_trend"],
  "export": {"width": 6, "height": 4.5, "dpi": 300, "files": ["result.svg", "result.pdf", "result.png"]}
}
```

Add plugin-specific facts that help reproduce or interpret the figure (statistical method,
thresholds, number of items per group, colour assignment). Keep it JSON-serialisable and small.

## Stability

Parameter names are a public API: saved projects and examples use them. Renaming or removing a
parameter requires a MAJOR version bump, an alias read in `plot.R` for at least one release, and
updated examples.
